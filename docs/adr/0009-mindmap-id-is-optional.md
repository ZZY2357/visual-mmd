# mindmap 节点的 id 是可选的，不自动生成

> **状态：accepted**

mindmap 的节点 id 是可选语法：`id[显示文本]` 里的 `id` 可以省略，省略时节点在 mermaid 模型里
`nodeId` 与显示文本是同一个串。因此 app 新建节点一律落**纯文本**（`新节点`），不自动生成 `n1`
这类机器 id；只有用户在属性面板显式填入 ID 时才把节点改写成 `id[显示文本]` 的分裂形式。

理由：源码是唯一交付物（ADR-0008），自动生成 id 会往用户的语法里塞机器命名；而 id 在 mindmap
语法里不参与任何引用（没有"用 id 连线"的语义），缺席不影响表达能力。

派生后果（实现时必须遵守）：

- **分离 id 必然引入形状**：mermaid mindmap 没有"无形状但 id ≠ 显示文本"的写法，
  `NewId[文本]`（方框）是唯一形态；所以设置 id 会改变节点外观，这是语法必然，不是缺陷。
- id 的字符集受 `id` 与形状的边界约束：不能含空白、圆括号、方括号、花括号；重复 id 合法
  （mermaid 不报错，且无引用语义可冲突）。
- 画布寻址**不依赖**语法 id：mindmap 节点仍按源码位置序寻址（`mindmap-node:N` / DOM `node_N`），
  与 ADR-0007 的 data-id 机制无关；改 id 不得影响选中与高亮。

## 清除 id 时的形状取舍（工单 05 裁定，2026-09-29 确认）

清空「节点 ID」字段要还原成什么形态，取决于原节点是否**本来就带形状**：

- 节点原本是纯文本（无形状）→ 设 id 时被补上默认方框（`User Input` → `UserNewInput[User Input]`）；
  清除时**连方框一起去掉**，退回纯文本（`User Input`）。
- 节点原本带**用户自选形状**（圆角 `( )` / 圆 `(( ))` / 六边形 `{{ }}` 等）→ 清除时**保留形状**，
  只去掉 id 前缀（`myid(圆角)` → `(圆角)`；`((思维导图))` 的根节点清除后仍是 `((思维导图))`）。

判定规则（`mindmap.ts:426`）：清除 id 时把 `shapeType === 'square'` 视为**分离引入的默认方框**并丢弃，
其余形状一律保留。理由是分离永远且只引入方框，故「方框」与「分离产物」在语法上不可区分。

**已知取舍**：若用户**刻意**把某节点选成方框（而非因设 id 被补），清除 id 会连这个方框一起去掉，
即"刻意方框"在清除后不可保留。

**为什么这么定**：

- 清除 id 必须能与设置 id **往返恒等**（未触碰文本逐字不变）：`User Input` → 设 id → `UserNewInput[User Input]`
  → 清 id → `User Input`。要做到这点，分离引入的方框必须无条件去掉。
- 用户明确裁定「保留**自选**形状」：非方框形状只可能来自用户的显式语法，保留它们同时满足往返恒等
  （原文本即带该形状）；把方框也保留会破坏第一条往返恒等，故方框例外。

行为由单测钉住：`src/lib/pipeline/__tests__/mindmap.test.ts` 的
`清 id：还原纯文本节点（分离引入的方框一并去掉）`、`清 id：圆角等用户自选形状保留`、
`清 id：根节点圆形保留（root((思维导图)) → ((思维导图))）`、
`设 / 清往返：新增的 id 前缀可完全撤销（未触碰文本逐字不变）`。
