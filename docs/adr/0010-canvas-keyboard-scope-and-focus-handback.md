# 画布键盘监听挂在容器上，编辑提交后显式归还焦点

> **状态：accepted**

画布键盘（Tab/Enter/Delete/方向键）的 keydown 监听挂在**画布容器**元素上，不挂 window：
焦点在代码面板或任何输入框时事件根本到不了容器，天然满足"只在画布聚焦时拦截"，不需要在
监听器里做"当前焦点在哪"的判断。代价是**画布必须真的持有焦点**，这个代价在 2026-09 的验收里
暴露为 bug：内联编辑提交后输入框卸载，React 19 不会把焦点还给已移除的元素，焦点落到 `<body>`，
于是"Tab 添加子节点"在连续操作时第二次就失效。

因此配套约定：**凡是画布内的编辑动作结束且意图是"继续在画布上操作"时，必须显式把焦点归还容器**。
具体来说：Enter/Escape 提交内联编辑 → 归还；点击画布空白/节点 → 归还；而失焦提交（用户点到画布
之外，如代码面板）→ **不归还**，否则会把用户从代码面板硬拽回画布。

被否掉的替代方案：把监听升到 window。它会让全站 Tab/Enter 被劫持，污染代码面板的 `indentWithTab`
与所有输入控件，且"光标在代码面板里按 Tab 究竟是缩进还是加节点"这类冲突无法自然消解。
